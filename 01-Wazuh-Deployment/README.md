# 01 — Wazuh Deployment

This section documents the deployment and baseline configuration of the Wazuh platform used in the home lab.

## Lab deployment recorded in the notes

- Wazuh server: Ubuntu virtual machine.
- Deployment method: official Wazuh installation assistant, all-in-one mode.
- Components: Wazuh Manager, Wazuh Indexer, Filebeat, and Wazuh Dashboard.
- Hypervisor: VMware.
- Endpoint agents: Windows and Linux systems.

The Wazuh Manager version was later confirmed directly on the running lab server as **v4.7.5 (revision 40720)**. The Windows agent installation notes also reference package version 4.7.5. The exact installed versions of the Indexer, Dashboard, and each endpoint agent have not yet been independently confirmed.

## Installation procedure recorded

Download the installation assistant for the selected Wazuh release from the official packages repository. The original notes used:

```bash
curl -sO https://packages.wazuh.com/4.7/wazuh-install.sh
ls -l wazuh-install.sh
```

The notes then used:

```bash
sudo bash wazuh-install.sh -a -i
```

- `-a`: all-in-one deployment.
- `-i`: bypasses the operating-system compatibility check.

**Important:** bypassing the compatibility check does not make an unsupported OS/release combination officially supported. The notes used Ubuntu 24.04 with this override. Do not present that combination as an enterprise-supported deployment without checking the Wazuh support matrix for the exact release.

For a fresh deployment, use the installation procedure and supported operating systems documented for the Wazuh version you actually intend to run.

## Service health checks

The original lab notes recorded all three services as active:

```bash
sudo systemctl status wazuh-manager
sudo systemctl status wazuh-indexer
sudo systemctl status wazuh-dashboard
```

After a reboot, the notes used:

```bash
sudo systemctl start wazuh-indexer wazuh-manager wazuh-dashboard
```

For troubleshooting, inspect each service separately and review the Wazuh logs rather than assuming that a successful systemd start means the full stack is healthy.

## Dashboard access

Find the server address on the Ubuntu VM:

```bash
ip address
```

Open the dashboard using HTTPS on the configured dashboard address and port (the notes recorded port 443). A self-signed certificate warning may appear in a lab deployment. Use the administrator credentials generated by the installer.

**Credential hygiene:** the original notes contained an installer-generated administrator password. It has deliberately not been copied into this repository. If that password is still active, rotate it immediately. Never store generated passwords in Git, screenshots, shell history, or public documentation.

## Endpoint enrollment

The notes describe enrolling Windows agents through the Wazuh Dashboard:

1. Select the Windows operating system.
2. Enter the Wazuh Manager address.
3. Assign a meaningful agent name based on the endpoint hostname.
4. Use the generated installation command for the selected agent version.
5. Start the Wazuh agent service.
6. Confirm that the endpoint appears as active and that events arrive.

The original notes contain a Windows MSI URL for agent 4.7.5 and a private lab address. Do not reuse the old package blindly; select a compatible agent package for the deployed manager version and substitute the current manager address.

On Windows, service status can be checked with:

```powershell
Get-Service WazuhSvc
Start-Service WazuhSvc
```

## Centralized agent configuration

Wazuh agent groups can distribute shared configuration from the manager. The notes created separate `Windows` and `Linux` groups under:

```text
/var/ossec/etc/shared/
```

The intended group configuration file is:

```text
/var/ossec/etc/shared/<GROUP_NAME>/agent.conf
```

Use the Wazuh agent-group management workflow to create groups and assign agents. Do not manually copy a stale `merged.mg` file as a substitute for group management. Add configuration inside an `<agent_config>` block, validate it, then confirm that the intended agents received it.

Example Windows Sysmon collection block:

```xml
<agent_config>
  <localfile>
    <location>Microsoft-Windows-Sysmon/Operational</location>
    <log_format>eventchannel</log_format>
  </localfile>
</agent_config>
```

Example Linux authentication log collection block:

```xml
<agent_config os="Linux">
  <localfile>
    <location>/var/log/auth.log</location>
    <log_format>syslog</log_format>
  </localfile>
</agent_config>
```

Validate the actual file path and configuration using the validation command supported by the installed Wazuh release. The notes recorded use of:

```bash
sudo /var/ossec/bin/verify-agent-conf
```

Then verify group assignment and synchronization, and confirm the resulting events in the dashboard.
