Wazuh detection tuning — correlation rule creation
Find the base rule SID that fires for a single failed Windows logon
The built-in Wazuh rule that matches each failed Windows logon in this lab is 60112 (confirmed by inspecting Wazuh alerts). That base rule must be referenced by the correlation rule so Wazuh can count repeated matches.
Do not assume a fixed SID — always verify the actual rule.id from an alert containing the Event ID 4625. Use the alerts view in the Wazuh dashboard or inspect /var/ossec/logs/alerts/alerts.json.
Add the custom correlation rule
Place the following block into /var/ossec/etc/rules/local_rules.xml on the Wazuh manager:

<group name="windows,bruteforce">
  <!-- Correlation rule: triggers when rule 60112 has matched 5 times within 60 seconds -->
  <rule id="100100" level="10" frequency="5" timeframe="60">
    <if_matched_sid>60112</if_matched_sid>
    <description>Custom: 5 Windows failed logons within 60 seconds — Possible brute-force attack</description>
  </rule>
</group>




Explanation of fields:

id="100100": a unique custom rule id (choose an id that does not collide with built-in rules).
frequency="5" timeframe="60": triggers when the referenced base rule (60112) matches 5 times in 60 seconds. These are attributes on <rule>they must be attributes, not child elements. If used incorrectly the manager will fail to start with an XML parsing error.
<if_matched_sid>60112</if_matched_sid>: reference to the base rule SID that matches a single failed logon event.
<group>bruteforce,windows</group>: labels attached to generated alerts so hunts and filters are simpler




sudo systemctl restart wazuh-manager
sudo systemctl status wazuh-manager -l
sudo tail -n 200 /var/ossec/logs/ossec.log



note :

If errors like Invalid option 'frequency' appear, ensure the frequency and timeframe are attributes on the <rule> element (not child tags), and check for any other <frequency> occurrences in other rules. Fix any syntax issues and restart.
After successful restart, the manager will load the local rules and accept the new correlation rule.
