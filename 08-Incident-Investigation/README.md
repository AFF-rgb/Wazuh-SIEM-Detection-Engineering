# 08 — Incident Investigation

This section defines a repeatable analyst workflow for investigating Wazuh alerts generated by the lab projects.

## Investigation workflow

1. **Triage:** identify alert severity, rule ID, timestamp, agent, and alert description.
2. **Validate telemetry:** inspect the raw event and decoded fields; confirm the event source and whether the alert is expected.
3. **Scope:** identify the affected endpoint, user/account, source IP, destination, and related events.
4. **Build a timeline:** correlate preceding and subsequent authentication, process, file, network, and account events.
5. **Assess impact:** determine whether access succeeded, privilege changed, persistence was established, or files/logs were modified.
6. **Respond:** recommend containment or remediation appropriate to the lab and document any automated response.
7. **Close out:** record evidence, root-cause assessment, limitations, and lessons learned.

## Investigation scenarios

- SSH authentication failures followed by a successful login.
- Sudo activity and root-shell creation.
- New local account and SSH authorized-key modification.
- Authentication log tampering.
- Cron persistence.
- Windows RDP failures followed by a successful logon.
- Suspicious Windows process and Sysmon activity.
- Active Directory account and group membership changes.
- Suricata network alerts correlated with endpoint telemetry.

## Minimum case record

For each investigation, capture:
- Case/reference ID.
- Alert and rule metadata.
- Affected agent and operating system.
- Relevant user/account and source/destination fields.
- UTC or clearly identified timezone timestamps.
- Related events and timeline.
- Analyst assessment and confidence.
- Containment/remediation recommendation.
- Validation result and remaining uncertainty.

Before publication, replace only passwords, SSH private keys, and hashes with `<REDACTED>`. Preserve IP addresses, MAC addresses, hostnames, usernames, timestamps, and other technical details. Do not publish password values, private-key material, or hashes.
